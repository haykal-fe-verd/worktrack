# WorkTrack Project Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the empty WorkTrack repository into a running Laravel + Inertia/React + PostgreSQL + Docker Compose skeleton, ready for Fase 1 feature work (Employee, Job, JobPeriod, Assignment, Attendance modules) to begin on top of it.

**Architecture:** Laravel app lives at the repository root (alongside `docs/`). Docker Compose runs six services — `app` (PHP-FPM), `web` (Nginx), `postgres`, `redis`, `queue-worker`, `scheduler` — all built from one custom PHP image. Frontend is Inertia.js + React + TypeScript via Laravel Breeze's React starter, styled with Tailwind (bundled by Breeze).

**Tech Stack:** Laravel (latest stable via Composer, no version pin), PHP 8.3, Inertia.js + React + TypeScript (Laravel Breeze react-ts stack), Tailwind CSS, PostgreSQL 16, Redis 7, Docker Compose, `spatie/laravel-permission`, `maatwebsite/excel`.

**Spec:** [docs/superpowers/specs/2026-09-09-worktrack-mvp-design.md](../specs/2026-09-09-worktrack-mvp-design.md) §8 (Arsitektur Teknis) — this plan implements only the infrastructure/scaffolding prerequisites for that spec, not the Fase 1 feature modules themselves.

## Global Constraints

- Stack is fixed: Laravel + Inertia.js + React + Docker + PostgreSQL (spec §8, PRD §10) — do not substitute Vue, Livewire, or SQLite.
- PostgreSQL 16+ (PRD §10).
- NIK and No. Rekening must be stored as strings, never numeric (PRD Asumsi A4) — not exercised in this plan, but the `users`/scaffold migrations must not set a precedent of numeric-casting free-text identifiers.
- No hard deletes of historical data anywhere in the app (PRD Asumsi A8) — not exercised in this plan, noted for downstream feature plans.
- Everything must run via Docker Compose; no task should require PHP/Composer/Node installed on the host.

### Task 2: Docker Compose infrastructure (app, web, postgres, redis, queue-worker, scheduler)

**Files:**
- Create: `docker/php/Dockerfile`
- Create: `docker/nginx/default.conf`
- Create: `docker-compose.yml`
- Create: `.dockerignore`

**Interfaces:**
- Consumes: the Laravel skeleton from Task 1 (`public/index.php` as the Nginx/PHP-FPM entrypoint).
- Produces: a `docker compose up` environment reachable at `http://localhost:8080`, with Postgres reachable from the `app` container at host `postgres:5432` and Redis at `redis:6379` — Task 3 depends on these exact hostnames/ports.

- [ ] **Step 1: Write the PHP-FPM Dockerfile**

```dockerfile
# docker/php/Dockerfile
FROM php:8.3-fpm

RUN apt-get update && apt-get install -y \
    git unzip libpq-dev libzip-dev libonig-dev \
    && docker-php-ext-install pdo pdo_pgsql zip \
    && apt-get clean && rm -rf /var/lib/apt/lists/*

COPY --from=composer:2 /usr/bin/composer /usr/bin/composer

WORKDIR /var/www/html
```

- [ ] **Step 2: Write the Nginx site config**

```nginx
# docker/nginx/default.conf
server {
    listen 80;
    index index.php index.html;
    root /var/www/html/public;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass app:9000;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
    }

    location ~ /\.(?!well-known).* {
        deny all;
    }
}
```

- [ ] **Step 3: Write `docker-compose.yml`**

```yaml
services:
  app:
    build:
      context: .
      dockerfile: docker/php/Dockerfile
    container_name: worktrack-app
    volumes:
      - .:/var/www/html
    networks:
      - worktrack
    depends_on:
      - postgres
      - redis

  web:
    image: nginx:1.27-alpine
    container_name: worktrack-web
    ports:
      - "8080:80"
    volumes:
      - .:/var/www/html
      - ./docker/nginx/default.conf:/etc/nginx/conf.d/default.conf
    depends_on:
      - app
    networks:
      - worktrack

  postgres:
    image: postgres:16-alpine
    container_name: worktrack-postgres
    environment:
      POSTGRES_DB: worktrack
      POSTGRES_USER: worktrack
      POSTGRES_PASSWORD: worktrack
    volumes:
      - worktrack-postgres-data:/var/lib/postgresql/data
    ports:
      - "5432:5432"
    networks:
      - worktrack

  redis:
    image: redis:7-alpine
    container_name: worktrack-redis
    networks:
      - worktrack

  queue-worker:
    build:
      context: .
      dockerfile: docker/php/Dockerfile
    container_name: worktrack-queue-worker
    command: php artisan queue:work --tries=3
    volumes:
      - .:/var/www/html
    depends_on:
      - app
      - postgres
      - redis
    networks:
      - worktrack

  scheduler:
    build:
      context: .
      dockerfile: docker/php/Dockerfile
    container_name: worktrack-scheduler
    command: >
      sh -c "while true; do php artisan schedule:run --verbose --no-interaction; sleep 60; done"
    volumes:
      - .:/var/www/html
    depends_on:
      - app
      - postgres
      - redis
    networks:
      - worktrack

networks:
  worktrack:
    driver: bridge

volumes:
  worktrack-postgres-data:
```

- [ ] **Step 4: Write `.dockerignore`**

```
node_modules
vendor
storage/logs
storage/framework/cache
storage/framework/sessions
storage/framework/views
.git
docs
```

- [ ] **Step 5: Build and start the stack, verify Nginx serves the Laravel welcome page**

```bash
sleep 5

```

Expected: `OK` printed. If it fails, run `docker compose logs app web` and fix the reported error before continuing.

### Task 3: Configure environment for PostgreSQL and Redis

**Files:**
- Modify: `.env`
- Modify: `.env.example`

**Interfaces:**
- Consumes: the `postgres`/`redis` service hostnames and credentials defined in Task 2's `docker-compose.yml`.
- Produces: a working `DB_*`/`REDIS_*`/`QUEUE_CONNECTION` config that Task 4 (Breeze) and Task 5 (package migrations) rely on for `php artisan migrate` to succeed.

- [ ] **Step 1: Update `.env` with Postgres and Redis connection settings**

Edit `.env` so these keys have exactly these values (Laravel's installer already created the other keys — leave those as generated):

```
DB_CONNECTION=pgsql
DB_HOST=postgres
DB_PORT=5432
DB_DATABASE=worktrack
DB_USERNAME=worktrack
DB_PASSWORD=worktrack

REDIS_HOST=redis
REDIS_PASSWORD=null
REDIS_PORT=6379

QUEUE_CONNECTION=redis
SESSION_DRIVER=redis
CACHE_STORE=redis
```

- [ ] **Step 2: Apply the same values to `.env.example`**

Mirror the exact same block into `.env.example` (this is the template committed to git — `.env` itself stays untracked).

- [ ] **Step 3: Generate the application key and run the default migrations against Postgres**

```bash
docker compose exec app php artisan key:generate
docker compose exec app php artisan migrate
```

Expected: migration output ends with `INFO  Running migrations.` followed by the default Laravel migrations (e.g. `0001_01_01_000000_create_users_table`) marked `DONE`, no errors.

- [ ] **Step 4: Verify the tables exist in Postgres**

```bash
docker compose exec postgres psql -U worktrack -d worktrack -c '\dt'
```

Expected: a table list including `users`, `sessions`, `cache`, `jobs`.

- [ ] **Step 5: Commit**

```bash
git add .env.example
git commit -m "Configure PostgreSQL and Redis connections"
```

(`.env` itself is git-ignored by Laravel's default `.gitignore` — do not force-add it.)

## Definition of Done

- `docker compose up -d --build` brings up all six services with no restart loops (`docker compose ps` shows all `Up`/`running`).
- `http://localhost:8080/login` renders a styled Inertia+React login page.
- `docker compose exec app php artisan migrate` runs clean against Postgres, including Breeze and spatie/laravel-permission tables.
- `README.md` lets a new engineer get from `git clone` to a running app without asking anyone a question.
- Nothing in this plan touches Employee/Job/JobPeriod/Assignment/Attendance domain code — that starts in the next plan, built on top of this skeleton.
