# shadcn/ui Migration — Sub-Project 1 (Setup + Layout + Auth) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install and configure shadcn/ui (keeping the PLN brand palette), build the toast/flash-message infrastructure, and migrate the app's shell (both layouts) and all Auth/Profile pages onto shadcn primitives — without touching any backend business logic in Employee/Job/Users modules.

**Architecture:** shadcn/ui is not an npm package with a fixed API surface — its CLI copies component source directly into this repo (`resources/js/Components/ui/*.tsx`), wired through a small `cn()` class-merge helper and CSS custom properties consumed by Tailwind's existing color system. Once the primitives exist, each subsequent task swaps the old Breeze-scaffold components (`PrimaryButton`, `TextInput`, `Modal`, etc.) for the new shadcn equivalents in one file group at a time — layouts first, then Auth pages, then Profile pages — leaving the old components in place (untouched) because Employee/Job/Users pages still import them until their own sub-projects migrate.

**Tech Stack:** Laravel 13 (PHP 8.4), Inertia.js + React 18 + TypeScript, Tailwind CSS v3 (the actively-wired version — see Task 1 note), shadcn/ui, Radix UI primitives, `sonner` for toasts.

**Spec:** [docs/superpowers/specs/2026-09-12-shadcn-ui-migration-design.md](../specs/2026-09-12-shadcn-ui-migration-design.md) — this plan implements §2 (Sub-Project 1) and the shared §3 (Dialog/Sheet pattern reference, not yet exercised by this sub-project since Auth/Profile pages stay full pages per §2.5).

## Global Constraints

- No backend business logic changes outside `HandleInertiaRequests`, `ProfileController`, and `PasswordController` (and only the flash-message additions specified in Task 2 — validation/auth logic in those controllers is untouched).
- Tailwind v3 is the **active** version in this repo (`@tailwind base/components/utilities` directives, `tailwind.config.js`, `postcss.config.js` with plain `tailwindcss`/`autoprefixer` plugins). The unused `@tailwindcss/vite` v4 devDependency and its absence from `vite.config.ts` is pre-existing scaffold cruft — do not wire it in, do not remove it, it is out of scope.
- **Case-collision hazard:** this repo's existing component folder is `resources/js/Components/` (capital C). On a case-insensitive filesystem (macOS default, which this project's contributors use), a new lowercase `resources/js/components/` directory would collide with it. shadcn's config MUST point its `ui`/`components` aliases at the existing capital-C `Components` folder (see Task 1's `components.json`) — never let the CLI create a new lowercase `components/` directory.
- Do not delete or modify the existing Breeze-scaffold components (`PrimaryButton.tsx`, `SecondaryButton.tsx`, `DangerButton.tsx`, `TextInput.tsx`, `InputLabel.tsx`, `InputError.tsx`, `Checkbox.tsx`, `Modal.tsx`, `Dropdown.tsx`, `NavLink.tsx`, `ResponsiveNavLink.tsx`) in this plan — Employee/Job/Users pages still depend on them until their own sub-projects migrate.
- Keep the topbar navigation structure (no sidebar) — an already-settled decision (U4).
- No new full-page routes/controllers in this plan — every file touched already exists; this is a pure view-layer + small-flash-message change.
- Follow this codebase's PHP conventions: explicit return types, `authorize()` returning `true` pattern is N/A here (no new FormRequests in this plan).
- Run `vendor/bin/pint --dirty --format agent` after any PHP change, `npx tsc --noEmit` after any TypeScript change, and `php artisan test --compact` before every commit.

- [ ] **Step 3: Write the toast hook**

```ts
import { usePage } from '@inertiajs/react';
import { useEffect } from 'react';
import { toast } from 'sonner';
import { PageProps } from '@/types';

export default function useFlashToast() {
    const { flash } = usePage<PageProps>().props;

    useEffect(() => {
        if (flash?.success) {
            toast.success(flash.success);
        }
    }, [flash?.success]);

    useEffect(() => {
        if (flash?.error) {
            toast.error(flash.error);
        }
    }, [flash?.error]);
}
```

                        <div className="mt-6">

                                Password

                            <Input

                                type="password"
                                name="password"
                                ref={passwordInput}
                                value={data.password}
                                onChange={(e) =>
                                    setData('password', e.target.value)

                                className="mt-1 block w-3/4"
                                autoFocus
                                placeholder="Password"
                            />

                            {errors.password && (
                                <p className="mt-2 text-sm text-destructive">
                                    {errors.password}
                                </p>
                            )}
                        </div>

                        <DialogFooter className="mt-6">
                            <Button
                                type="button"
                                variant="secondary"
                                onClick={closeModal}
                            >
                                Cancel
                            </Button>

                            <Button
                                type="submit"
                                variant="destructive"
                                disabled={processing}
                            >
                                Delete Account
                            </Button>
                        </DialogFooter>
                    </form>
                </DialogContent>
            </Dialog>
        </section>
    );
}
